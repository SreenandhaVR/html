Accesbility

Accesibility means making message usable bt as many people as possible.While it mostly focuses on supporting people with disabilities,this practice benefits everyone.Even if you don't have a disability.We might be browsing on an mobile device with a smaller screen or using a slow internet connection.Accessible techniques can improve the experience for everyone in these situations as well.The core principle is simple:Everyone should be able to access to the web and in some places it's actually the law.The w3c has a complete guide to accessibility laws and policies by country.The legal requirements vary by region,but they usually apply to government agencies and sectors such as banking,telecommunications,libraries,educational institutions and transportation.The W#C has also created the Web Content Accessibility Guidelines,which outline the best practices for making web content accessible.This guide is extensive and has lot of detailed information,so I recommend starting hte WCAG At a Glance article.

Accessible Rich Applications(ARIA) basics

Informational websites tend to have a pretty straightforward structure because content is generally static.It doesn't change very oftern.As a result,informational websites are often more accessible than dynamic websites.Dynamic websites and web applications,however,tend to be more complex because the content changes more often.For example,on social media platforms,content is constantly updated in response to various user actions,like posting or liking a post.As the web became more advanced and interactive,new accessibility challenges popped up.Adding more complex features and dynamic content using Javascript libraries sometimes resulted in less semantic HTML code,make it harder for screen readers to understand.There is a technology that can help solve this problem called Accessible Rich Applications(ARIA).

Special set of attributes that provide additional semantics and improve accessibility.

First Rule of ARIA use

  • If you can use a native HTML element,or attribute with the semantics and behavior you require already built in,instead of require already built in,instead of re purposing an element and adding an ARIA role,state or property to make it accessible then do so.
  • Used to determine whether we actually need it at all.According to W#C documentation,ARIA attributes are not used for accessibility unless they are necessary to support a feature that doesn't already have a semantic HTML element.
